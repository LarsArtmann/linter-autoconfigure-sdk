## e) WHAT WE SHOULD IMPROVE (session-derived lessons)

1. **Pre-tag doc enumeration must include ALL claims-bearing docs** — ROADMAP
   alongside README/CHANGELOG/FEATURES. A tag freeze makes doc rot permanent;
   the checklist should ask "which files make claims that this release
   invalidates?"
2. **Sub-claim verification discipline.** When writing "verified", every field
   of the verification query must cover every field of the change. The
   fork-syncing miss is the pattern to kill.
3. **Propagation-blocked verifications need a bounded retry loop or an
   explicit completion downgrade.** I did neither for pkg.go.dev — the final
   summary did mention it, but the todo was marked completed.
4. **Rehearse verification programs** (compile mentally, check field
   requirements) before first run — the SDK's own validation doc was right
   there to consult.
5. **Challenge inherited assumptions.** "Cannot view images" was false for
   this toolchain; one `view` call would have either cleared T23's first step
   or found text overflow in the PNG.
6. **Daemon stall is now a known release-flow risk** (2/2 commits this
   session). Until understood, release procedures should include an explicit
   "await daemon push, else escalate" decision point rather than an ad-hoc
   inference mid-flight.
